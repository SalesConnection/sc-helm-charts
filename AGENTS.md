# AGENTS.md

Guidance for AI coding agents working in this repository. See
[agents.md](https://agents.md) for the format.

## What this repo is

A Helm chart monorepo for SalesConnection's Kubernetes workloads. Charts under
`charts/` are packaged and published to GitHub Pages
(`https://salesconnection.github.io/sc-helm-charts`) by
`helm/chart-releaser-action` on every push to `main`.

## Project structure

- `charts/<name>/` — one Helm chart per directory. All are `type: application`.
  - `Chart.yaml` — metadata, `version`, `appVersion`, and (for umbrella charts)
    `dependencies`.
  - `values.yaml` — default values.
  - `values.schema.json` — optional JSON Schema validation (e.g. `batch-reminder`).
  - `templates/` — Kubernetes manifests plus `_helpers.tpl`.
- `charts/caction/` is an umbrella chart. It depends on `repeat-job`, `noti`,
  and `qr-generator`, pinned in `Chart.lock` and vendored as `.tgz` files under
  `charts/caction/charts/`.
- `charts/salesconnection/` is a large aggregate chart that deploys the whole
  platform directly from its own templates.
- `.github/workflows/release.yml` — the release pipeline.

## Conventions

- **Versioning is mandatory.** Bump the chart's `Chart.yaml` `version` (SemVer)
  on any change to its templates or values. The release action only publishes a
  chart when its `version` is new; a change without a version bump will not be
  released.
- `appVersion` tracks the deployed application version and need not be SemVer.
- Template helpers are namespaced per chart in `templates/_helpers.tpl`
  (e.g. `microservice.fullname`, `microservice.labels`,
  `microservice.selectorLabels`). Follow the existing names when adding helpers.
- Match the style and structure of the chart you are editing; do not introduce
  new tooling or restructure directories without being asked.

## Checks before committing

Run from the chart directory you changed:

```bash
helm lint .
helm template test-release . -f values.yaml
# umbrella charts (e.g. caction) only:
helm dependency update .
```

Confirm templates render without errors and that any `values.schema.json`
still validates `values.yaml`.

## Do not touch

- `Chart.lock` and the vendored `.tgz` files under `charts/caction/charts/`
  unless you are intentionally updating dependency versions (then update
  `Chart.yaml` dependencies and run `helm dependency update`).
- The `gh-pages` branch — it is generated by the release action.
- Untracked root-level `*.yml` / `*.yaml` values files (e.g. `br-values.yaml`,
  `sc-values.yml`). These are local, environment-specific values and are not
  part of the tracked chart source. Leave them alone.

## Release

Merging to `main` triggers `release.yml`: `chart-releaser-action` packages each
changed chart, publishes the package and an updated `index.yaml` to `gh-pages`,
and creates a per-chart tag (e.g. `microservice-1.3.0`).
